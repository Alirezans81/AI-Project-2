## معرفی پروژه

این سامانه مسئله زمان‌بندی مسابقات ورزشی را به‌صورت یک **مسئله ارضای محدودیت (CSP)** مدل‌سازی می‌کند.

هدف، تخصیص بهینه `(روز، ساعت، استادیوم)` به هر مسابقه است؛ به‌گونه‌ای که هیچ‌یک از قوانین لیگ نقض نشود.

| مفهوم | توضیح |
|-------|-------|
| **متغیرها** | هر مسابقه بین دو تیم یک متغیر CSP است |
| **دامنه** | تمام سه‌تایی‌های ممکن `(روز، ساعت، استادیوم)` |
| **محدودیت‌ها** | عدم تداخل استادیوم‌ها + استراحت تیم‌ها + مسابقات حساس |

## الگوریتم پیاده‌سازی‌شده

### Backtracking Search `[علیرضا نصیری]`

الگوریتم جستجوی بازگشتی با بررسی رو به جلو برای شناسایی زودهنگام بن‌بست:

```
1. انتخاب متغیر بدون مقدار (select_unassigned)
2. بررسی سازگاری مقدار کاندیدا (consistent)
3. اعمال Forward Checking روی دامنه متغیرهای باقی‌مانده
4. در صورت خالی شدن دامنه → Backtrack فوری
5. در صورت تخصیص کامل → بازگشت جواب
```

---

## محدودیت‌های مسئله

### ۱. محدودیت تداخل استادیوم `[علیرضا نصیری]`
در یک استادیوم مشخص، در یک ساعت مشخص از یک روز، **تنها یک مسابقه** برگزار می‌شود.

### ۲. محدودیت استراحت تیم‌ها `[رضا پیردیر]`
هیچ تیمی نمی‌تواند در یک روز بیش از **یک بازی** داشته باشد.

### ۳. محدودیت مسابقات حساس `[رضا پیردیر]` (بخش امتیازی)
هیچ دو مسابقه حساسی در یک **روز یکسان** نمی‌توانند برگزار شوند.

## پیش‌پردازش و بررسی امکان‌پذیری

قبل از شروع جستجو، دو بررسی ساده انجام می‌شود:

| شرط | توضیح |
|-----|-------|
| `N > S × D × H` | ظرفیت کل کافی نیست |
| `K > D` | بر اساس اصل لانه‌کبوتری، جا برای همه مسابقات حساس نیست |

در هر صورت: **`No Solution`** چاپ می‌شود.

## فرمت ورودی

```
S
Stadium1 Stadium2 ...
D
H
N
Team1 Team2
...
K
Team1 Team2
...
```

| پارامتر | توضیح |
|---------|-------|
| `S` | تعداد استادیوم‌ها |
| `D` | تعداد روزهای در دسترس |
| `H` | تعداد بازه‌های زمانی در هر روز |
| `N` | تعداد کل مسابقات |
| `K` | تعداد مسابقات حساس |

> **نکته:** ترتیب نام تیم‌ها در مسابقات حساس اهمیتی ندارد.  
> `Team_A Team_B` و `Team_B Team_A` یک مسابقه محسوب می‌شوند.

## جزئیات پیاده‌سازی

### `select_unassigned` `[علیرضا نصیری]`
انتخاب اولین متغیر بدون مقدار به ترتیب ایندکس.

### `consistent` `[رضا پیردیر]`
بررسی سه محدودیت اصلی قبل از تخصیص:
- تداخل `(روز، ساعت، استادیوم)` با مسابقات قبلی
- تداخل روز برای تیم‌های مشترک
- تداخل روز بین مسابقات حساس

### `forward_check` `[رضا پیردیر]`
پس از هر تخصیص، مقادیر ناسازگار از دامنه متغیرهای باقی‌مانده حذف می‌شوند:
- ترکیب `(روز، ساعت، استادیوم)` اشغال‌شده از همه دامنه‌ها حذف می‌شود
- کل روز برای تیم‌های درگیر از دامنه مسابقات هم‌تیمی حذف می‌شود
- اگر دامنه هر متغیری خالی شد → **بازگشت فوری**

### `backtracking` `[علیرضا نصیری]`
حلقه اصلی جستجو — ترکیب سه تابع بالا + شمارش Backtrack‌ها + مدیریت deep copy دامنه‌ها.

### `main` + بررسی امکان‌پذیری `[علیرضا نصیری]`
خواندن ورودی، ساخت دامنه‌های اولیه، پیش‌بررسی `N > S×D×H` و `K > D`، اندازه‌گیری زمان.

### تعریف Backtrack
هر بار که الگوریتم تمام مقادیر یک متغیر را امتحان کند بدون یافتن جواب، یک Backtrack شمارش می‌شود.

## گراف محدودیت (مجاورت متغیرها)

دو مسابقه در شرایط زیر همسایه هستند:
- دارای **تیم مشترک** باشند
- هر دو می‌توانند برای یک ترکیب `(روز، ساعت، استادیوم)` رقابت کنند
- هر دو **مسابقه حساس** باشند
